# 脚本与 SQL 治理

## 入口与归属

- 先读 `scripts/README.md` 的任务路由，沿用已有职责目录。脚本头必须按 `docs/coding-conventions.md` §19.5 写“用途、用法”；Python 也适用，公共库说明引用方式，测试脚本说明测试入口。
- 说明性注释及 Python 文档字符串使用简体中文；保留命令、协议名、工具指令与代码示例。必要说明关注隔离、顺序、并发、失败传播和资源释放，不逐行翻译代码。
- 路径变化同步调用方、README、配置、测试与 CI；运行 `check-script-governance.py` 和定向回归。根 db/migration 管 Flyway，scripts/db 管数据库操作，根 test-data 管共享场景数据，不为整理目录改写历史迁移。
- CI 机器基线归 `scripts/ci/baselines/`，按真实差异收紧，不盲目全量生成或扩张预算；工作流和复用 Action 分别在 `.github` 下对应 README 登记。

## 脚本审查

1. 从仓库文档和 CI 确认支持的操作系统、shell、运行时和调用方式。
2. 检查引用、未设置变量、管道退出码、临时文件清理、信号、路径处理和错误传播。
3. 复用集中配置和运行时辅助工具；区分有意默认值与意外硬编码的环境值。
4. 确保凭证没有被不必要地记录、嵌入或持久化。
5. 确认脚本有可发现入口，如 CI/workflow、任务运行器、文档、目录约定或明确的运维命令。
6. 测试/验收脚本按本地、容器和 CI 核对 profile、Locale/时区、服务端口、数据库与凭据来源；复用共享环境入口，场景变量保留可覆盖性。业务断言优先稳定错误码/key；翻译专项另用独立语言预期，不依赖运行机器的默认语言。

## SQL 审查

- 相比临时内嵌查询，优先使用独立参数化 SQL 或仓库既定 mapper 边界。
- 校验 schema 限定、租户条件、事务边界、可重复执行性和预期行数。
- 评估轮询、清理和批量操作的索引、查询计划、锁范围和处理上限。
- 检查动态拼装 SQL 文件名或命令的脚本；只搜索字面引用不足以证明某资产未使用。

结构演进和 Flyway 发布使用 `database-migration-safety`。本 skill 负责脚本及运维/查询 SQL，不负责迁移设计。

## 验证与清理

- 在受支持的平台或 shell 上运行语法/lint 检查，并在可行时验证 fallback 路径。
- 将脚本、SQL 或文档标记为未使用前，检查动态引用、自动发现约定、手工 runbook 和历史记录。
- 不要只因找不到直接源码调用方就删除运维资产。

## 当前文档与脚本的方法补充

修改跨平台脚本、公共库或数据库客户端fallback时，按需读取[脚本运行时、共享库与副作用核对](references/runtime-methods.md)。只加载相关方法，不把文档列出的操作自动加入执行范围。
