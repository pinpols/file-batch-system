# 事务、批量执行与文件恢复的历史方法

<a id="WRK-1"></a>

## WRK-1 事务与租户上下文时间线

适用于回滚丢重试、异步回写或跨库操作。按每一步列出执行线程、租户/RLS/MDC、数据源、事务代理、提交点和可回滚副作用。MDC里有tenant不代表PG会话已绑定RLS；内层服务结束后的回写还须检查上下文是否已清除，线程复用后也不能残留前租户。

区分本地业务提交、位点提交、Outbox写入和外部发送。`REQUIRES_NEW`/after-commit/方法引用注册需要追实际代理调用，不凭注解推断。跨数据源提交不能假定共享事务；业务成功但结果未知的窗口要用既有幂等、回执及恢复协议验证。

验证分别覆盖外层回滚、切线程、线程复用、业务提交后崩溃和上报响应丢失；实时面板可回查的丢推送与业务消息丢失不使用相同严重度或相同补偿方案。

<a id="WRK-2"></a>

## WRK-2 批量运输的逐项身份与提交边界

适用于claim/report/renew批量优化。先核对谁真正调用了批端点，不从“接口存在”推导Worker已使用；CLAIM、REPORT和BUNDLE业务聚合分别建事实表。沿每项task、tenant、invocation/版本身份追认领、等待、续租、执行、上报和确认。

构造认领成功/竞争失败、执行失败、瞬时上报失败、响应丢失和跨租混合批；核对已经领取但等待执行的任务仍受租约维护。批内单项失败不应被整体HTTP 200掩盖；实际是逐项事务、整批事务还是其他隔离方式，读当前代码和真实数据库证据，不强制采用旧savepoint建议。

Offset按当前消费协议验证：一个partition中前项未确定时，不能因后项完成就越过该项确认；重投已成功项需验证去重与外部效果。往返次数的确定性单测只证明网络调用数，吞吐、锁竞争和恢复需独立负载证据。

<a id="WRK-3"></a>

## WRK-3 文件位点与物理持久化的一致性

适用于导出续跑、导入位点或跨阶段恢复。分别找业务/文件写入完成、flush/fsync、位点持久化、正式发布和清理的先后关系，在相邻边界间设置崩溃场景。

检查位点已存但文件缺失/变短、文件写出但位点未存、尾部半条记录、游标类型不可恢复及临时目录不在当前节点。恢复不能单靠cursor；按当前实现验证安全字节位点、截断边界、格式头尾及不支持格式的全量回退。旧chunk拼接与单文件截断是不同方案，不同时当成当前实现。

最终校验行数、主键集合、金额/控制总数及格式合法性，必要时比较校验和；任务SUCCESS、文件存在或MinIO上传成功不足以证明内容无重无漏。当前实现与操作见[Checkpoint手册](../../../../docs/runbook/platform-worker-checkpoint-howto.md)及[文件完整性](../../../../docs/design/file-integrity-recovery.md)。

<a id="WRK-4"></a>

## WRK-4 永久坏数据、可恢复等待与未知结果

适用于持续重试或日志风暴。区分确定性无效配置/数据、成员尚未到齐、瞬时依赖故障及外部结果未知；记录多轮重试的状态、原因和资源消耗。降日志级别或加counter只改善可见性，不等于根因关闭。

新增隔离终态前核对状态枚举、查询、监控投影、审计、权限和受控人工恢复；没有新状态授权时不自动实现。以坏数据重复扫描、迟到成员补齐、瞬时故障恢复和修正后重评四类案例验证；不能把仍可恢复的组永久丢弃，也不能盲目重试已产生外部效果的未知操作。
