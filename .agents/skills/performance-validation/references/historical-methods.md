# 资源预算、读取放大与业务吞吐验证方法

<a id="PERF-1"></a>

## PERF-1 从资源占用时间核算并发

适用于连接、线程、队列或IO调优。汇总每个副本及平台/业务数据源的连接上限，区分Quartz、事务、后台维护与业务准入的真实池；追到等待发生时是否持有连接、锁、文件或执行许可。不要把API并发许可总和当成集群业务容量。

逐段检查网络connect/read/整体超时、future等待、取消和释放；方法返回Future不代表调用方不阻塞，虚拟线程也不增加数据库或对端容量。故障恢复窗口内同时记录线程/连接等待、队列深度、重试、续租和任务残留；先证明瓶颈再改变线程模型。

<a id="PERF-2"></a>

## PERF-2 读取放大与分片完整性

适用于大文件或分页分区。记录源数据量、实际读入字节/扫描行数、分片数、内存峰值和业务产出，比较单片与多片；N个任务各扫描全量再过滤仍可能有N倍读取成本，吞吐不能只由任务并发推断。

Range切片先验证编码、引号跨行、记录边界、压缩和格式约束；keyset区间先验证稳定排序、游标类型、偏斜与分区互斥/并集。优化前后对账主键集合、行数、控制总数、格式和实际扫描量；不能通过关闭分区过滤却保留多片来制造快读。具体格式支持由当前实现决定。

<a id="PERF-3"></a>

## PERF-3 控制面与数据面的独立分母

适用于task storm、混合Worker及日终排空。分别定义task/s与rows/s、作业wall-time与stage耗时、准入/等待/拒绝/成功/失败/UNKNOWN的分母；Kafka lag为零或HTTP 200不能替代业务排空。

同条件比较镜像/dirty源码、资源限制、PG/Kafka/存储配置、并发与数据形状；微基准、单机全链路和目标环境分别留证。检查不同Worker/租户公平性、长短任务互相影响和结束后CREATED/READY/RUNNING残留，保留失败与恢复数据，不能只计算成功子集或复用旧千万行耗时当当前能力。
