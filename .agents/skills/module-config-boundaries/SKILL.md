# 模块与配置边界

## 梳理所有权

1. 阅读仓库模块图和构建配置，不要只凭目录名称推断运行时所有权。
2. 确认受影响模块的 API、持久化、配置和资源分别由谁负责。
3. 追踪依赖方向，检查循环依赖、重复所有权、隐藏的跨模块写入，以及仅供测试的依赖是否泄漏到生产。
4. 对配对客户端/服务，依据权威来源核对契约和生成产物。

## 配置生命周期

- 找出配置的唯一事实来源、默认值、校验、密钥处理、持久化、应用/重载行为和回滚语义。
- 确保应用代码、本地脚本、容器、部署清单和文档中的配置键/环境变量一致。
- 多种语言或部署入口存在漂移风险时，避免重复维护同一默认值。
- 区分为兼容性而有意固定的配置，与意外的版本或取值漂移。

## 验证

- 使用仓库已有的依赖边界、配置同步、资源所有权和契约检查。
- 测试无效、缺失、默认和覆盖值；配置持久化时也验证重启/重载行为。
- 契约变化时更新归属文档和示例，不要把临时实现细节复制进通用指导。

依赖方向、配置事实来源、环境/版本对齐和资源所有权使用本 skill；结构所有权及迁移发布风险使用 `database-migration-safety`。
