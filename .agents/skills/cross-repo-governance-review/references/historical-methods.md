# 前后端历史交互问题的复现方法

<a id="UI-1"></a>

## UI-1 操作目标与迟到响应

适用于租户/Workflow切换、保存草稿、批量操作和异步查询。记录点击时的tenant、resource/version、操作键与草稿键，发送后切换租户/目标或离开页面，再让旧请求完成；确认写回、删草稿、toast和刷新仍归属原目标，旧响应不能覆盖新上下文。

区分加载、空、错、取消和业务拒绝状态；catch返回空数组或把确认取消与真实请求失败都吞掉应逐路径验证。保存成功要回读服务端持久化结果，批量结果要逐项展示。缺通知不能直接定为数据故障，按用户旅程影响判断。

<a id="UI-2"></a>

## UI-2 图编辑器往返与组件生命周期

适用于DAG编辑/预览或编辑器替换。验证节点改名后边引用、稳定ID与nodeCode的关系，导入→编辑→保存→重载的拓扑等价，以及多个合法终点等后端接受场景。

分别验证KeepAlive重新激活、路由离开、事件重新绑定、销毁/重建和草稿恢复；删除某编辑器不能证明这些用户风险消失。当前采用X6或Mermaid须查代码，不能继承旧“X6已删除”报告；前后端校验边界以现行模型及API为准。

<a id="UI-3"></a>

## UI-3 真实布局、翻译与焦点证据

适用于响应式、暗色、i18n和可访问性复核。使用实际路由/角色/主题和中英文长文本检查窄屏、软键盘、溢出/横向滚动、弹窗焦点进入/恢复、键盘可达与状态的非纯颜色表达；按项目支持矩阵选视口，不照搬旧像素建议。

从请求错误码到翻译键、可见消息和trace核对完整链路；生成类型不能验证表单必填/枚举/数值范围或服务端拒绝的反馈。记录真实DOM/截图与axe、Lighthouse或键盘实测结果，不能将静态预测评分、组件库声明或旧阈值当执行通过。相关专项仍路由配对前端技能，不自动授权修改配对仓。
