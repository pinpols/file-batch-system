# Git 与 Pull Request 流程

## 范围

本流程适用于 Git 状态变更和 PR 交付。仓库说明及用户明确要求优先。

## 流程

1. 操作前确认仓库根目录、当前分支、remote、worktree、工作区状态和已有差异。
2. 需要最新信息时先 fetch；比较工作分支和目标基线，并检查确切变更集。
3. 保留无关及未提交改动；没有明确授权时，不做破坏性清理或改写历史。
4. 提交或推送前复核分支和暂存差异。提交应聚焦，避免误加生成物或秘密信息。
5. 创建或更新 PR 前确认目标分支、标题、范围和必需检查。CI 实际成功完成前，不得称其通过。
6. 仅在用户要求且仓库策略允许时合并。合并后核实远端状态，再清理本地分支或 worktree。
7. 报告 commit/PR 标识、检查状态、合并状态和剩余本地分叉情况。

## 安全规则

- 不要猜测分支名、默认分支、仓库路径或合并策略。
- 不要为消除歧义而强推、reset、删分支或丢弃改动；先检查，必要时询问。
- 配对仓库应分别检查，并将 API/schema 变更与其调用方对齐。
