# 代码审查与验证

## 审查流程

1. 确认审查基线并检查完整差异，包括生成文件和相邻调用方；不要把工作区中与本次变更无关的内容混入结论。
2. 按变更涉及的边界追踪输入校验、认证授权、租户/所有权、状态转换、重试、持久化和错误映射。
3. 检查并发、幂等、事务范围、消息顺序及兼容性等行为是否有明确依据。
4. 对每个疑似问题先构造最小触发条件，沿调用链和数据流追到根因；区分根因与表面症状，不以增加宽泛防御代码替代因果分析。
5. 检查测试是否验证关键结果和失败路径。修复缺陷时优先添加能暴露原问题的定向测试，再验证修复后的行为；若无法先复现，说明原因及替代证据。
6. 将确认缺陷、纵深加固建议和未验证假设分开陈述。

## 验证

- 先读仓库指导并确认适用命令、模块依赖和受支持环境；多模块 Maven 验证要包含所需上游模块（通常使用 `-am`）。
- 先跑针对性静态检查和测试，再按风险或用户要求扩大到完整门禁。
- 查看命令真实退出码和进程结束状态；管道、后台任务或会话结束不能替代成功证据。被中断的任务不能报告为通过。
- 对外部依赖明确区分 mock、容器集成、本机真实服务、staging 演练和生产证据。
- 收尾前对照变更清单核实每项修改、测试和残余风险；不要仅凭日志中的局部成功信息宣布完成。

数据库迁移、模块/配置边界、脚本/独立 SQL 或负载测试应使用对应的专项 skill，避免在此重复专项清单。

## 发现与报告

先列可操作的问题并按严重度排序。每项说明文件位置、触发条件、影响和建议的复现/验证方式。没有发现问题时，说明审查范围及仍未覆盖的风险。
