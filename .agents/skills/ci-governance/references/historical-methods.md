# 历史CI提速与覆盖修正方法

<a id="CI-1"></a>

## CI-1 测量关键路径并验证选测盲区

适用于缓存、分片、路径过滤和TIA选测。拆分排队、环境准备、构建、各测试片与聚合耗时；用同revision、规则、依赖和冷热缓存比较关键路径，不能将旧预期收益当实测。

核对反射加载、MyBatis XML、动态脚本、测试profile、生成物及共享fixture是否进入依赖图；不知道影响范围时应沿现行全量回退，不凭Java依赖分析跳过XML相关测试。正例覆盖业务代码/共享资源/契约/新模块变更，反例覆盖确实不影响代码的文档变化；变更检测没有PR base等输入时核实安全回退。

旧“PR不跑IT”“skip算成功”、固定分片数或合并队列步骤不继承为当前策略；实际workflow、required checks与授权决定现行行为。提速导致验证推迟的代价及主线失败处理必须明确，不能靠取消required结果或降低enforce模式证明性能收益。

<a id="CI-2"></a>

## CI-2 验证守卫的扫描域与误报

适用于门禁已绿但新模块/变体仍出错。逐项核对发现范围、输入解析、触发路由、enforce/report/ignore、聚合状态和真实测试产物。守卫只扫两个模块不能证明新Worker或Trigger覆盖；fixture文字中写了约束不代表runner真的断言。

保留一个应拦和相近合法样例，再核对增量/全量路径与历史预算迁移。搜到注解、旧报告高危标签或问题数量不能单独定级；规则修正基于最小复现，不通过扩大白名单、删除检查或吞掉退出码关闭失败。
