# 历史数据库审查的取证方法

<a id="DB-1"></a>

## DB-1 用实际约束和角色验证不变量

适用于幂等键、租户列、归档镜像与RLS审查。先列热表/归档/分区/触发器/Mapper/运维SQL的实际结构，再按业务重复判定核对NOT NULL、UNIQUE、部分谓词、外键和ON CONFLICT目标。空值是否应视为同一业务键要单独确定，不能通用规定所有UNIQUE列禁止NULL。

缺直接tenant列不自动证明越租：沿全局ID、外键所有权、SQL条件、角色和RLS验证实际可达路径。测试跨租读取/修改、错误父子关联和重复插入，用受限、非owner、无bypass角色证明策略；超级用户可访问不是应用权限漏洞证据。旧报告中的示例DDL须重新验证，不按文字建议直接回放。

归档漂移同时比列名、类型和nullability；删除历史镜像或调整清理策略还要确认真实读者和恢复需求。验证应说明是空库完整迁移、存量升级还是实际恢复，不互相替代。

<a id="DB-2"></a>

## DB-2 旧表切换与索引移除的恢复证据

适用于分区切换或索引合并。区分新库初始化、存量重建和在线切换；分别验证写入路由、唯一性/幂等约束、租户边界、复制/WAL、双向行对账及失败恢复。旧表保留天数与备份存在都不能替代恢复演练。

索引移除先覆盖完整业务周期并记录统计重置、读副本与低频查询；用真实谓词、排序和部分索引条件比较计划，`idx_scan=0`不是充分证据。保存完整catalog定义及恢复耗时，确认约束依赖；不复制旧表名、旧DROP模板或固定迁移版本。详细查询取证沿用[SQL性能技能](../../sql-query-performance/SKILL.md)及[数据库治理](../../../../docs/design/database-schema-governance.md)。
