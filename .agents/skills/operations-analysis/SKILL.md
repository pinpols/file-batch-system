# 运维分析总控（只读）

## 安全边界

本 Skill 仅用于分析与建议。所有操作必须只读；不得因诊断需要自行扩大为环境变更或故障演练。

禁止：部署或构建后部署、启停/重启进程或容器、执行 Flyway 或其他迁移、写数据库/消息/对象存储、删除或清理数据和文件、改配置或权限、修改集群资源、运行压测/故障注入、调用会产生业务副作用的 API，或执行无法确认只读的脚本。

若某项结论只有通过写操作、重启、故障注入或其他有副作用的实验才能确认，停止在证据边界处，说明所需操作、影响和验证目标；不擅自执行。只读命令也应先检查目标环境和命令行为，避免读取或输出密钥、令牌及个人信息。

## 分析与路由

1. 明确环境、时间范围、目标服务和用户关心的运行现象。检查当前分支/工作区状态，保留未提交改动。
2. 优先读取权威 Runbook、当前配置、部署定义、代码调用链、现有日志与验证记录；区分当前证据、历史记录、静态推断和未验证假设。
3. 只读盘点后按问题路由专项 Skill：
   - 环境变量、容器配置、Helm/Compose 和版本漂移：`configuration-governance`。
   - 调度、业务日、misfire、补跑和暂停恢复：`scheduler-correctness`。
   - Worker、任务状态、claim/lease、重试和 outbox：`worker-pipeline-review`。
   - 数据库结构或迁移风险：`database-migration-safety`；查询热点：`sql-query-performance`。
   - 备份、PITR 和恢复目标：`disaster-recovery-validation`，仅做方案/证据审阅，不发起恢复演练。
   - 容量与性能：`performance-validation`，仅分析已有数据和测试计划，不发起负载。
   - Shell/SQL 运维资产：`script-sql-governance`，审阅脚本，不执行其中的变更操作。
4. 建议动作分清只读核实、低风险准备步骤和需要单独授权的写操作；列明触发条件、预期状态变化、回滚/恢复要求及责任边界。建议不等于已执行。

## 报告

按风险排序输出：现象与环境基线、只读证据及来源、影响范围、可能根因和置信度、尚未验证项、建议处置步骤。明确本次未执行部署、写入、重启、清理、压测或故障注入；不得将日志缺失或静态推断表述为运行成功/失败的证明。
