## 风险决定测试层级

| 层级 | 应验证的边界 | 可用证据与限制 |
|---|---|---|
| 静态检查、格式和编译 | 语法、类型、依赖、文档/契约同步 | 不证明 SQL、事务、消息和业务结果 |
| 单元/组件 | 状态转换、日历规则、参数与配置校验、错误分类、游标和资源关闭 | 使用确定性输入；替身验证不冒充真实依赖 |
| 真实依赖集成 | PostgreSQL SQL/事务/CAS/RLS/归档、Kafka offset/重投、对象存储完整性 | 复用最小依赖环境并验证关键失败窗口 |
| E2E | 服务入口到持久化业务结果、消息和恢复的完整主链 | 不能只断言 HTTP、日志、终态或文件存在 |
| 系统/目标环境 | 容量、进程故障、HA、PITR、升级回滚与外部交付 | 单独授权和安排环境；记录版本、故障时间线、RTO/RPO及业务对账 |

不以固定比例或“只保留四条 E2E”限制覆盖。新增用例选择能暴露目标风险的最小层级；多线程、跨事务、租户或外部副作用组合保留必要的系统测试。

## 必须保持的业务验证面

| 范围 | 主要断言 |
|---|---|
| Workflow 与批次日 | START/END、JOB、GATEWAY、WAIT 的合法推进；直接 START→END 和 WAIT 跳过分别验证；开日登记义务不预建全部 Job，业务日/区间快照保持 |
| 批量发起 | 多 Workflow 各自启动、逐项结果和重试；预检与正式执行分开；重试不能把多个目标合为一个运行 |
| 分发与执行 | DB→Outbox→Kafka→CLAIM→EXECUTE→REPORT；状态和 Outbox 同事务，认领 CAS、版本围栏和租约拒绝有效 |
| 重放与外部效果 | 审批使用冻结快照；已执行但响应丢失保持未知，先对账再决定恢复；不能按“无记录”推断未执行 |
| 文件与业务数据 | 输入校验、分片互斥/完整性、行数/金额/校验和、导出产物、分发回执与失败恢复；SUCCESS 不替代对账 |
| 租户与授权 | 真正受限角色执行 SQL/HTTP；跨租读取、写入、审批、下载和后台异步路径被拒绝，不能由超级用户测试替代 |
| 控制与运维 | 暂停/续跑、drain、重试耗尽、DLQ审批、过期租约、Outbox重投及进程重启后业务收敛 |
| API/SDK | Controller/DTO/OpenAPI/前端生成类型和五语言协议行为一致；fixture、真实 transport 与目标环境分别留证 |

## 测试环境与 fixture

优先复用 `batch-test-support`、邻近场景 fixture 和根 `test-data/`。共享 profile/default 集中维护；仅给当前用例设置必要覆盖，不为了避免差异启动整套无关依赖。纯逻辑不依赖完整 Spring 上下文，集成测试按既有基类选择最小真实依赖集合。

Java 测试中的 JDBC 操作沿用 `JdbcTemplate`，SQL 使用独立具名变量和适合的文本块；轮询查询保留在原回调，不能提取到回调外改变时间语义。预期值与实现需要独立，避免同源计算漏检漂移。断言完整业务结果及关键失败路径，测试资源按用例拥有权清理。

## 故障、性能与发布验证

先记录成功基线，再按单故障、恢复、必要组合故障推进：数据库断连/回滚、Kafka波动/重投、对象写失败、Worker重启/排空、外部渠道超时及回执丢失。容器替身、单机多容器与真实多主机应分别标注。容量同时记录准入、等待、拒绝、失败、UNKNOWN和最终排空，不能只统计成功子集。

执行入口和参数以脚本及 [CI Runbook](../runbook/ci.md) 为准。`staging-gate.yml` 的存在不表示完成部署、负载或生产回滚验收。当前环境缺口从 TODO 和验收矩阵读取，不把旧 Phase 1/2 表格中的“未覆盖”转成新待办。

## 每轮证据要求

报告记录代码基线及 dirty 范围、环境与真实/替身依赖、实际命令和退出码、测试总数/失败/错误/跳过、首个有效失败、日志与产物、业务结果和未验证项。未运行、被中断、SKIP和外部阻塞分别列出；历史报告中的“编译通过”“全绿”不继承为当前结果。

完成项回写对应方案/矩阵和 TODO；保留失败证据及未关闭的目标环境事项。复跑只围绕新的改动、失败或尚未解决的风险扩展，避免以重复执行数量代替验收判断。
