## 2026-10-31 并发恢复与 Full CI 剩余用例稳定化

- 并发依赖释放恢复：父节点校验发现已绑定同一 TriggerRequest 的 JobInstance 时按重复请求幂等短路，不再把请求覆盖为 REJECTED；新增单测覆盖同请求实例短路与其它请求实例仍拒绝两条路径。
- ReportInvocationFence 集成测试：共享全量库和 worker 选择缓存会保留同租户历史 ONLINE worker，用例改用专属 workerGroup，使派单只能命中本用例 seed worker，避免 claim 永久 READY。
- catch-up 审批 E2E：把 TriggerRequest=`LAUNCHED` 纳入同一有界等待，避免在异步启动链完成前读到 `PROCESSING` 中间态。
- 恢复锚点 Kafka offset 集成测试：拉长后台恢复扫描轮询间隔，避免 park 后的锚点立即被真实 launch 回收成 REJECTED，保持“稍后恢复”的 PENDING 断言确定。
- 回退 #1274 误加到 `shouldConvergeCoverage_whenConfigurationAndSettlementRace` 的结算业务日变更：该变更让预置 `nextFire` occurrence 落入查询业务日，`selectCountSql` 恒返回 1 造成确定性失败；bounded-coverage 用例的 CUTOFF/SETTLED 偶发仍需单独定位，本次不改其业务日。
- WorkerReportLost DISPATCH 恢复 E2E：launch 前隔离同租户其它 DISPATCH worker 并等待 Kafka 消费组 STABLE，避免 Full CI 共享库下 outbox 定向 topic 派给历史 worker、当前子进程永远收不到派发。

## 2026-10-31 测试汇总与 Flyway 门禁

- Full CI 剩余时序测试稳定化：JobNodeDispatch 的 schedule 次数断言改为至少两次（后台 waiting-partition 重评估属合法追加）；Sensor 重启的 deadline 探测等待 30s→90s；bounded-coverage E2E 的结算业务日改到次日，避免首批 coverage 上限恰好覆盖完整首日导致 CUTOFF/SETTLED 竞态。

- Full CI E2E 稳定性：WorkerReportLost 系列在派发前显式等待独立 Worker 的 Kafka 消费组完成分区分配，避免消费者入组前消息按 latest 跳过导致整段等待超时；并放宽报告等待窗口以适配低配 CI。

- 编排测试的 MyBatis SQL 使用日志级别控制，减少 CI 日志截断；需要时可启用 Mapper 调试输出。

- PR 的 Trigger 与 Worker 测试分片并行执行并合并覆盖率；Full CI 拆分编排长类与业务提交恢复长尾，合并覆盖数据并保留原有测试与必需检查。

- 拆分耗时 PR 测试并合并覆盖率，汇总 Java、E2E 和多语言 SDK 测试结果；缺失报告与跳过明确区分。
- 编排恢复/并发集成测试稳定化：批次边界断言期间关闭后台 @Scheduled 派发，只由用例显式触发批次；认领等待窗口延长并在超时时输出任务状态诊断，消除共享上下文调度与慢 CI 造成的偶发失败。
- Full CI 剩余 flaky 集成/E2E 测试稳定化：重试计划去重键唯一化；Quartz 重启清理先解绑 trigger 再删 job；重复派发场景的 claim 次数断言改为至少 N 次，保留副作用幂等精确断言。
- 恢复/并发集成测试与 catch-up E2E 再稳定化：全量共享库中隔离 seed worker，避免历史 ONLINE worker 被调度选中导致 claim 永久 READY；misfire 自动恢复与断言竞争时容忍 PENDING→REQUESTED，重启持久化断言仅在 PENDING 时校验。
- WDI 合并后移除存量 Flyway SQL 漂移的临时例外，恢复连续增量迁移检查。
- Rust 自托管示例使用认领返回的实际参数，保留结构化值。

- **Java 日志与异常输出规范**：服务/测试统一使用 SLF4J/Logback 或 JUnit `TestReporter`，禁止直接标准输出和 `printStackTrace()`；未预期故障将 Throwable 交由日志框架记录，预期 fallback 使用 `SwallowedExceptionLogger`，周期重试避免重复整栈。唯一标准输出例外为 `security-scan` CLI，并由 Java 日志治理门禁限定。

### 2026-09-24
- **ADR-035 Java SDK HTTP 实现边界**：核心 SDK 继续保持 Spring-free，允许以 OkHttp 5 作为内部控制面 HTTP 实现以获得可验证的 IPv4/IPv6 Happy Eyeballs；OkHttp 类型不得暴露到公共 API，SDK 发布物继续遵守 `< 2 MB` 约束，平台内部服务发现与网络策略不随之改变。

### 2026-09-14
- **ADR-027/ADR-042 重任务边界落地**：资源画像只负责把任务路由到稳定 Worker 池，Kubernetes 继续负责节点与 Pod 调度；`workerPoolCode` 与具体 `workerCode` 实例身份分离，专用池仅消费自己的 direct topic。平台以 PostgreSQL 事务锁实施全局活跃作业硬上限，以租户/队列并发、共享 QPS、Worker 负载和 Dispatch 渠道健康构成统一准入链；生产不得关闭全局硬上限。明确仍不把 WAITING 描述成无限队列，也不以本地队列替代 Kafka、不自研 Kubernetes Scheduler；WAITING 存储硬上限和任务派发 Kafka lag gate 继续作为 ADR-042 独立增强。
- **重任务容量承诺口径**：并行任务以墙钟跨度计算 records/s 与 MB/s，累计任务耗时仅用于估算资源成本；上线承诺必须同时给出数据量、批量窗口、p95、失败率、PG WAL/IO、Kafka lag 和 Worker 饱和度证据，控制面 tasks/s 不得直接外推重任务 SLA。
