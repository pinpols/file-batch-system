# Dispatch 密钥版本运行时语义

## 决策

- 新建作业实例时，平台解析其 Dispatch 渠道引用，并把 `secretRef + secretVersionId + versionNo` 写入实例参数快照。密钥明文不进入作业快照、Kafka/outbox 或日志。
- Workflow 实例为其自身 TASK/FILE_STEP 节点固定引用版本；通过 JOB 节点拉起的子作业是独立实例，在子实例创建事务中固定版本，不继承调用方传入的内部绑定字段。
- 排队、执行和重试都使用同一个固定版本；轮换只影响之后创建的实例。不得在执行或重试时静默切换到当前版本。
- 每次外部投递前，Dispatch Worker 按租户和固定版本 ID 读取受保护载荷，并校验版本仍在有效期且未撤销。撤销优先于实例快照，阻断尚未发出的请求及后续自动重试。
- 只有成功进入投递调用所需的凭据会短暂注入运行态渠道配置；投递与可选回读结束后立即移除。
- 未解析、引用不匹配、解密失败、字段不允许、版本撤销或过期均 fail-closed，不回退到明文配置或最新版本。

## 故障与恢复边界

- 撤销前已经发出的网络请求无法召回。若远端结果不确定，系统不因密钥问题自动重新发送；运维应先核对下游结果，再决定是否以新实例补发。
- 正常轮换不撤销旧版本。旧版本按 `effective_to_at` 或明确撤销策略失效，避免排队实例因轮换被无声改写。
- 部署切换前已创建且尚未投递的旧任务没有版本快照；若它引用 Secret，升级后的 Worker 会 fail-closed，不会擅自读取最新版本。上线前需盘点这类存量任务，确认下游状态后重建实例或人工处置。
- 配置写入、审计和撤销状态由 Console/配置域负责；实例快照由 Orchestrator 在 launch 事务中生成；Worker 只按快照读取并执行，不拥有密钥版本选择权。
- 不扩展到平台资源快照/恢复、租户路由重构或容量公平性调度；这些属于独立需求。

## 验收范围

单测覆盖 launch 固定版本、缺失版本拒绝、Worker 精确版本读取、撤销拒绝、凭据清理和不可重试错误；真实 PostgreSQL 集成测试覆盖迁移约束及租户/版本/撤销/有效期过滤。CI 与生产环境验证仍以各自运行结果为准。
